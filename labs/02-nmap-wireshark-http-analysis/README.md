# Lab 02 — HTTP Traffic Analysis using Wireshark

---

## Objective

To capture and analyze HTTP traffic using Wireshark in order to understand how web communication works, identify sensitive data exposure, and reconstruct full sessions.

---

## Lab Setup

- **Attacker Machine:** Kali Linux (192.168.56.101)  
- **Target Machine:** DVWA Web Server (192.168.56.102)  
- **Network Type:** VirtualBox Host-Only Network  

### Tools Used

- Wireshark  
- Firefox Browser  
- DVWA (Damn Vulnerable Web Application)  

---

## Traffic Generation

HTTP traffic was generated by accessing:
'''bash
http://192.168.56.102

### Activities Performed

- Visiting the homepage  
- Navigating to `/twiki/`  
- Accessing `/twiki/readme.txt`  
- Logging into DVWA  

---

## Packet Capture

- **Network Interface:** `eth1`  
- **Capture Filter:** None  

### Display Filters Used
'''bash
http

---

## HTTP Request & Response Analysis

### HTTP Request

The client sends a request:
'''bash
GET / HTTP/1.1

#### Important Headers

- `Host: 192.168.56.102`  
- `User-Agent: Firefox`  
- `Accept: text/html`  

This request asks the server for the main webpage.

---

### HTTP Response

The server responds with:
'''bash
HTTP/1.1 200 OK

#### Response Contains

- HTML content  
- `Content-Type: text/html`  

This confirms successful communication.

---

## Filtering HTTP Requests

Using:
'''bash
http.request

### Observed Requests

- `/`  
- `/favicon.ico`  
- `/twiki/`  
- `/twiki/readme.txt`  

This shows that a single page load generates multiple requests for resources.

---

## Normal HTTP Traffic

Typical traffic includes:

- HTML files  
- Text files  
- Images (`.gif`, `.ico`)  

This reflects normal browser behavior when loading a webpage.

---

## Credential Exposure Analysis

A POST request was captured during DVWA login:

'''bash
POST /dvwa/login.php HTTP/1.1


### Captured Credentials

- **Username:** `admin`  
- **Password:** `password`  

### Key Findings

- Credentials are transmitted in **plain text**  
- HTTP does **not provide encryption**  
- Data is visible in packet payload  

### Security Risk

This demonstrates a **Man-in-the-Middle (MITM) vulnerability**, where an attacker can intercept sensitive data without compromising the server.

---

## TCP Stream Analysis

To reconstruct the session:

'''bash
Right-click → Follow → TCP Stream


### Reconstructed Data Includes

- HTTP request headers  
- Server response  
- HTML content  
- Session cookies (`PHPSESSID`)  

### Importance

- Enables full session reconstruction  
- Allows attackers to extract:
  - Credentials  
  - Cookies  
  - Web content  

---

## Normal vs Sensitive Traffic

| Type              | Description                                      |
|-------------------|--------------------------------------------------|
| Normal Traffic     | HTML, images, and text file requests             |
| Sensitive Traffic  | POST request containing credentials              |
| Security Risk      | Data transmitted in plain text                   |

---

## Connection to Previous Lab

In the previous lab, the TCP three-way handshake (SYN → SYN-ACK → ACK) was analyzed.

This lab builds on that by showing how HTTP operates on top of TCP to transfer application-layer data.

---

## Key Observations

- HTTP operates on top of TCP  
- Data is transmitted in plain text  
- Multiple requests are generated per webpage  
- Credentials can be exposed in POST requests  
- Session cookies are visible and exploitable  
- Entire sessions can be reconstructed from captured traffic  

---

## Mitigation Strategies

To prevent these vulnerabilities:

- Use **HTTPS (TLS encryption)**  
- Implement **HSTS (HTTP Strict Transport Security)**  
- Use secure cookies (`Secure`, `HttpOnly`)  
- Avoid transmitting sensitive data over HTTP  
- Monitor network traffic for anomalies  

---

## Real-World Relevance

HTTP traffic analysis helps in:

- Detecting credential leakage  
- Identifying suspicious activity  
- Monitoring data exfiltration  
- Understanding attacker behavior  

---

## Conclusion

This lab demonstrated how HTTP traffic can be captured and analyzed using Wireshark. It showed that unencrypted communication exposes sensitive information such as login credentials and session cookies. TCP stream reconstruction further highlights how entire sessions can be recovered. These findings emphasize the importance of using HTTPS to secure web communications.
